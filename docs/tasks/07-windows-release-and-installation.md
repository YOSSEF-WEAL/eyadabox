# 07 — Windows Release and Installation

## What exists today

- The application is developed as a React/Vite web interface.
- Tauri wraps that interface as a native Windows desktop application and keeps the local SQLite database in the Windows application-data directory.
- The file currently created during local desktop verification is:
  - `src-tauri/target/debug/clinic_desk.exe`
- This is a **debug/development executable**. It depends on the local development workflow and is not intended to be sent to clinic users.

## What clinic users should receive

Clinic users should receive the NSIS installer generated by Tauri, not the debug executable. The installer:

- installs Clinic Desk normally on Windows;
- creates a Start Menu/installed-app entry;
- runs without Vite, Node.js, Rust, or developer tools on the clinic computer;
- stores the SQLite database in the current Windows user's application-data directory, separate from the installed program files.

## Release command

Run this command only when a reviewed release is requested:

```powershell
npm run tauri:build
```

This command first builds the web frontend and then builds the signed-ready Tauri release bundle. It is intentionally not run as part of normal development.

## Expected installer location

After a successful production build, look under:

```text
src-tauri/target/release/bundle/nsis/
```

The filename is generated from the product name and version, typically similar to:

```text
Clinic Desk_0.1.0_x64-setup.exe
```

Treat the file that actually appears in this folder as the authoritative installer filename, because Tauri may vary it by version, architecture, or bundle configuration.

## Recommended release checklist

1. Confirm the version in `src-tauri/tauri.conf.json`.
2. Run the web and desktop development checks and test patient, practitioner, appointment, settings, Arabic, and English workflows.
3. Back up a test database and confirm the installed build opens it correctly.
4. Run `npm run tauri:build` only after the user explicitly asks for the release installer.
5. Install the generated NSIS installer on a clean Windows test account or virtual machine.
6. Verify it opens without the Vite server and that data remains after closing and reopening.
7. Deliver only the generated installer from `bundle/nsis`, together with a versioned release note and database-backup guidance.

## Current decision

No production installer has been built yet. This is deliberate: the project rule requires an explicit request before any distributable executable, packaging, or release command is run.
